The problem

Accounts Payable is manual, slow, and error-prone

📥 Unstructured intake

Vendor invoices arrive by email as PDFs, scans, and HTML — no consistent schema.

🔎 Tedious matching

Each invoice is manually reconciled against a PO and Goods Receipt, line by line.

⚠️ Costly exceptions

Price/qty variances, missing POs and duplicates need judgement — and an audit trail.

The same reconciliation pattern also applies in reverse — matching inbound customer remittances to open AR items.

Objective

A contextual, agentic workflow — end to end

Shared mailbox→ Extract→ 2-/3-way match→ Post journal/ Escalate→ Audit

Straight-through when confident

Clean matches post a Payment Journal automatically.

Human-in-the-loop when not

Exceptions route to an approver; every decision is auditable back to the source email.

Pipeline · Ingestion

Provider-abstracted intake with a replay mode

Design

  • EmailProvider protocol → Graph / Gmail / folder replay
  • Extract & classify attachments (pdf/image/html)
  • Persist bytes + content SHA-256 for dedup
  • Replay-idempotent: already-seen emails skipped

Why folder replay

The whole pipeline runs and demos without live mailbox OAuth — Graph/Gmail are documented interface stubs behind the same protocol, swappable with one line.

Pipeline · Retrieval (RAG)

Semantic PO lookup — robust to messy invoices

POs are embedded (Ollama nomic-embed-text) and indexed in PGVector via LlamaIndex. An invoice is rendered into the same vendor + line-items + total space and matched by similarity.

  • Recovers the right PO even with fuzzy vendor names or a missing/garbled PO number
  • Feeds the matching engine with candidate POs

Design decisions & trade-offs

Deliberate, defensible choices

  • Mock ERP first — build immediately; swap a real sandbox behind the same client.
  • pypdfium2 for digital PDFs — Docling's layout pass dropped born-digital text; OCR reserved for scans.
  • Deterministic PO backstop — beats re-tuning an 8B model on a well-labelled field.
  • Durable exception queue over a pinned paused graph — production-sound & testable.
  • Schema-first contract — one Pydantic model set shared by every stage.
  • Injectable services — heavy LLM/vector paths faked for fast, local unit tests.
